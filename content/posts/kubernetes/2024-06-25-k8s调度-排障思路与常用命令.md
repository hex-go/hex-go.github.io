# 重要

Pod 调度失败通常有四种原因：资源不足、约束不满足（nodeSelector/affinity/taint）、调度器故障、抢占进行中。排查思路：看 Pod Events → 查节点状态 → 检查调度器日志 → 核对资源 Quota。

---

## 1. 基础诊断命令

| 命令 | 用途 |
|------|------|
| `kubectl describe pod <name>` | 查看 Pod Events（调度失败原因） |
| `kubectl get events --sort-by=.metadata.creationTimestamp` | 查看集群事件 |
| `kubectl top nodes` | 查看节点资源使用量（CPU/内存） |
| `kubectl top pods -A` | 查看 Pod 实际资源使用量 |
| `kubectl describe node <name>` | 查看节点 Capacity/Allocatable/Conditions |
| `kubectl get pods -A --field-selector=status.phase=Pending` | 列出所有 Pending Pod |
| `kubectl logs -n kube-system <scheduler-pod>` | 查看调度器日志 |

## 2. 按现象排查

### 2.1 Pod 一直 Pending

```bash
kubectl describe pod <name>
# Events:
#   Warning  FailedScheduling  0/3 nodes are available:
#   1 Insufficient cpu, 2 Insufficient memory.
```

| 原因 | Events 关键词 | 解决 |
|------|-------------|------|
| 资源不足 | `Insufficient cpu/memory` | 扩容节点或减少 requests |
| nodeSelector 不匹配 | `node(s) didn't match node selector` | 检查 Pod 的 nodeSelector 与节点标签 |
| nodeAffinity 不满足 | `node(s) didn't match node affinity` | 检查 affinity 规则 |
| Taint 不容忍 | `node(s) had taints that the pod didn't tolerate` | 添加 toleration 或去掉 taint |
| PVC 未绑定 | `persistentvolumeclaim not found` | 检查 PVC 状态 |
| GPU 不足 | `Insufficient nvidia.com/gpu` | 释放 GPU 或扩容节点 |

### 2.2 调度器不工作

```bash
# 检查调度器健康状态
kubectl get pods -n kube-system -l component=kube-scheduler
kubectl logs -n kube-system <scheduler-pod> --tail=100

# 检查调度器 Leader 选举
kubectl get endpoints kube-scheduler -n kube-system -o yaml
```

### 2.3 ResourceQuota 耗尽

```bash
kubectl describe resourcequota -n <namespace>
# Name:       compute-quota
# Resource    Used  Hard
# --------    ----  ----
# limits.cpu  18    20
# pods        52    50   ← 超限！
```

### 2.4 Pod 被驱逐

```bash
kubectl describe pod <name>
# Status: Failed
# Reason:  Evicted
# Message: The node was low on resource: memory.

# 查看节点条件
kubectl describe node <name> | grep -A5 Conditions
# Conditions:
#   MemoryPressure   True   ...
#   DiskPressure     False  ...
```

| 驱逐原因 | 触发条件 | 解决 |
|---------|---------|------|
| MemoryPressure | 节点内存使用率 > `--eviction-hard` 阈值 | 加内存或减少 Pod |
| DiskPressure | 节点磁盘使用率 > 阈值 | 清理磁盘或扩展 |
| PIDPressure | 节点 PID 数 > 阈值 | 减少 Pod 数或增加 `pid_max` |

## 3. 资源诊断

### 3.1 节点资源概览

```bash
# 查看节点可分配资源（Allocatable = Capacity - 系统保留）
kubectl get node <name> -o json | jq '.status.allocatable'
# {
#   "cpu": "8",
#   "memory": "32125332Ki",
#   "nvidia.com/gpu": "4"
# }

# 查看节点实际使用
kubectl describe node <name> | grep -A10 "Allocated resources"
# Allocated resources:
#   Resource           Requests      Limits
#   cpu                5500m (68%)   8000m (100%)
#   memory             12Gi (40%)    20Gi (66%)
```

### 3.2 查看哪些 Pod 占用最多资源

```bash
# 按 CPU requests 排序
kubectl get pods -A -o json | jq -r '.items[] | select(.status.phase=="Running") |
  "\(.metadata.namespace)/\(.metadata.name) \(
    .spec.containers[]?.resources.requests.cpu // "0m")"' | sort -k2 -h -r | head -20

# 按内存 requests 排序
kubectl get pods -A -o json | jq -r '.items[] | select(.status.phase=="Running") |
  "\(.metadata.namespace)/\(.metadata.name) \(
    .spec.containers[]?.resources.requests.memory // "0")"' | sort -k2 -h -r | head -20
```

### 3.3 检查节点容量与实际使用

```bash
# 哪些节点 CPU requests 占比最高
for node in $(kubectl get nodes -o name); do
  echo -n "$node: "
  kubectl describe $node | grep -A5 "Allocated resources" | grep "cpu" | head -1
done
```

## 4. 调度器性能排查

### 4.1 调度延迟

```bash
# 查看调度器 Metrics（如果开启了 Prometheus）
curl -s http://<scheduler>:10251/metrics | grep scheduler_scheduling_duration_seconds

# 调度器日志中的调度耗时
kubectl logs -n kube-system <scheduler-pod> | grep "scheduling latency"
```

### 4.2 调度队列积压

```bash
# 查看 Pending Pod 数量
kubectl get pods -A --field-selector=status.phase=Pending | wc -l

# 按优先级排序
kubectl get pods -A --field-selector=status.phase=Pending \
  -o custom-columns=NAME:.metadata.name,PRIORITY:.spec.priority
```

## 5. OOM Kill 排查

```bash
# 查看被 OOM Kill 的 Pod
kubectl get events -A | grep OOM

# 查看节点 dmesg
dmesg | grep -i "out of memory"

# 查看 Pod 的重启原因
kubectl get pod <name> -o json | jq '.status.containerStatuses[].lastState.terminated'
# {
#   "reason": "OOMKilled",
#   "exitCode": 137
# }
```
