## 1.简介

Linux 启动流程经常被简化成：

```text
BIOS -> GRUB -> Kernel -> init -> login
```

这个说法方向没错，但不够完整。现代 Linux 需要区分三条线：

1. **硬件 / 固件启动线**：BIOS 或 UEFI 做硬件初始化；
2. **内核启动线**：Bootloader 加载内核，内核挂载根文件系统；
3. **用户态初始化线**：PID 1 启动服务，最终提供登录环境。

### 2.2 BIOS / UEFI

固件负责最早期的硬件初始化。

| 项目 | BIOS | UEFI |
|------|------|------|
| 启动方式 | 读取 MBR 引导代码 | 读取 EFI System Partition 中的 `.efi` 文件 |
| 分区表 | 常见 MBR | 常见 GPT |
| 启动文件 | 磁盘前 446 字节引导代码 | `EFI/BOOT/*.efi` 或发行版自己的 EFI 文件 |
| 现代系统 | 逐步淘汰 | 主流方式 |

UEFI 场景下常见文件路径：

```text
/boot/efi/EFI/ubuntu/grubx64.efi
/boot/efi/EFI/centos/grubx64.efi
/boot/efi/EFI/BOOT/BOOTX64.EFI
```

### 2.3 Bootloader：GRUB

Bootloader 的主要职责：

1. 展示启动菜单；
2. 加载 Linux 内核文件；
3. 加载 initramfs；
4. 向内核传递启动参数。

常见文件：

| 文件 | 说明 |
|------|------|
| `/boot/vmlinuz-*` | 压缩后的 Linux 内核镜像 |
| `/boot/initrd.img-*` 或 `/boot/initramfs-*` | 初始内存文件系统 |
| `/boot/grub/grub.cfg` | GRUB 主配置文件 |
| `/etc/default/grub` | GRUB 默认参数配置 |

查看当前内核启动参数：

```bash
cat /proc/cmdline
```

示例：

```text
BOOT_IMAGE=/boot/vmlinuz-5.15.0 root=UUID=xxx ro quiet splash
```

### 2.4 Kernel 与 initramfs

内核被加载后，会完成以下动作：

1. 初始化 CPU、内存、调度器；
2. 初始化驱动；
3. 挂载 initramfs；
4. 根据启动参数找到真正的根文件系统；
5. 挂载 rootfs；
6. 启动第一个用户态进程。

initramfs 的作用：在真正的根文件系统挂载前，提供必要工具和驱动。

典型场景：

- 根分区在 LVM 上；
- 根分区加密；
- 根分区在 RAID 上；
- 需要提前加载存储驱动。

如果 initramfs 缺少必要驱动，可能出现无法挂载根文件系统：

```text
Kernel panic - not syncing: VFS: Unable to mount root fs
```

### 2.5 PID 1：systemd / init

内核启动的第一个用户态进程固定是 PID 1。

查看当前系统 PID 1：

```bash
ps -p 1 -o pid,comm,args
```

常见结果：

```text
PID COMMAND         COMMAND
  1 systemd         /sbin/init
```

现代主流发行版中，`/sbin/init` 通常是指向 `systemd` 的软链接。

```bash
ls -l /sbin/init
```

### 2.6 systemd target 与 SysV runlevel

旧 SysV init 使用 runlevel：

| Runlevel | 含义 |
|----------|------|
| 0 | 关机 |
| 1 | 单用户模式 |
| 2 | 多用户模式，不同发行版含义略有差异 |
| 3 | 多用户命令行模式 |
| 4 | 保留 |
| 5 | 图形界面模式 |
| 6 | 重启 |

systemd 使用 target：

| systemd target | 类似 runlevel | 说明 |
|----------------|---------------|------|
| `poweroff.target` | 0 | 关机 |
| `rescue.target` | 1 | 救援模式 |
| `multi-user.target` | 3 | 多用户命令行模式 |
| `graphical.target` | 5 | 图形界面模式 |
| `reboot.target` | 6 | 重启 |

查看默认 target：

```bash
systemctl get-default
```

设置默认 target：

```bash
systemctl set-default multi-user.target
systemctl set-default graphical.target
```

### 2.7 服务启动

systemd 根据 unit 文件启动服务。

常见 unit 类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| `.service` | 系统服务 | `sshd.service`、`docker.service` |
| `.socket` | Socket 激活 | `systemd-journald.socket` |
| `.target` | 一组 unit 的集合 | `multi-user.target` |
| `.mount` | 挂载点 | `home.mount` |
| `.timer` | 定时任务 | `logrotate.timer` |

常见目录：

```text
/usr/lib/systemd/system/
/lib/systemd/system/
/etc/systemd/system/
```

优先级通常是：`/etc/systemd/system/` 覆盖系统默认 unit。

查看服务启动耗时：

```bash
systemd-analyze
systemd-analyze blame
systemd-analyze critical-chain
```

查看某个服务状态：

```bash
systemctl status sshd
journalctl -u sshd -b
```

### 2.8 用户登录与 Shell 初始化

系统服务启动完成后，用户可以通过不同方式登录：

| 登录方式 | 关键组件 |
|----------|----------|
| 本地命令行 | `getty` + `login` |
| SSH | `sshd` |
| 图形界面 | display manager，例如 `gdm`、`sddm`、`lightdm` |

Bash 启动文件需要区分登录 Shell 和非登录 Shell。

| 场景 | 读取文件 |
|------|----------|
| 登录 Shell | `/etc/profile`，然后读取 `~/.bash_profile` / `~/.bash_login` / `~/.profile` 中第一个存在的文件 |
| 非登录交互 Shell | `~/.bashrc` |
| 非交互 Shell | 通常不读取上述文件，除非通过环境变量或参数指定 |

常见建议：

- 环境变量、PATH 等需要登录继承的内容放 `~/.profile` 或 `~/.bash_profile`；
- alias、prompt、补全等交互配置放 `~/.bashrc`；
- `~/.bash_profile` 中通常显式加载 `~/.bashrc`。

示例：

```bash
if [ -f ~/.bashrc ]; then
  . ~/.bashrc
fi
```

### 2.9 常见排查命令

| 目标 | 命令 |
|------|------|
| 查看内核参数 | `cat /proc/cmdline` |
| 查看当前内核 | `uname -r` |
| 查看 PID 1 | `ps -p 1 -o pid,comm,args` |
| 查看默认 target | `systemctl get-default` |
| 查看本次启动日志 | `journalctl -b` |
| 查看上次启动日志 | `journalctl -b -1` |
| 查看启动耗时 | `systemd-analyze blame` |
| 查看失败服务 | `systemctl --failed` |
| 查看服务依赖链 | `systemctl list-dependencies multi-user.target` |

## 3.总结

1. Linux 启动流程可以分为：固件初始化、Bootloader、Kernel、initramfs、rootfs、PID 1、服务启动、用户登录；
2. BIOS / UEFI 负责找到 Bootloader，GRUB 负责加载内核和 initramfs；
3. 内核启动后会挂载根文件系统，并启动第一个用户态进程 PID 1；
4. 现代 Linux 大多使用 systemd，target 取代传统 runlevel；
5. Shell 初始化发生在用户登录之后，不属于内核或 systemd 启动阶段。
