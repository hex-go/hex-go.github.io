# 重要

Go 1.8+ GC 使用并发三色标记 + 混合写屏障，STW 降至微秒级。核心设计取舍：编译器逃逸分析将短生命周期对象留在栈上使分代回收收益小；TCMalloc 内存分配减少了标记-整理的碎片化需求。

## 1. GC 算法演进

| 版本 | 算法 | STW 时长 |
|------|------|----------|
| Go 1.4 及以前 | 标记-清除（全程 STW） | 100ms+ |
| Go 1.5 ~ 1.7 | 三色并发标记 + 插入写屏障 + 栈重扫描 | 1-3ms（两次 STW） |
| Go 1.8+ | 三色并发标记 + 混合写屏障 | <100μs（一次 STW） |

1.5-1.7 为什么有两次 STW：

```text
┌─────┬─────────────┬─────────────┬─────────────┐
│ STW │   并发标记   │     STW     │  并发清扫     │
│ 开始 │ (应用+GC)   │     终止     │  (仅应用)    │
└─────┴─────────────┴─────────────┴─────────────┘
  ↑                 ↑               ↑
启用屏障           重新扫描栈       禁用屏障
扫描初始根                        完成标记
```

- 第一次 STW（准备阶段）：确保根对象在一致状态下被扫描，100-500μs
- 第二次 STW（终止阶段）：栈上没有写屏障，必须重新扫描所有栈来捕获变化，1-3ms

1.8+ 在栈上引入**混合写屏障**，消除了第二次 STW。

## 2. 三色标记法

三色标记将对象分为三类：

| 颜色 | 含义 |
|------|------|
| 白色 | 待标记对象，潜在垃圾 |
| 灰色 | 正在处理的根节点，待解析其引用 |
| 黑色 | 已标记，确认存活 |

**标记过程：**

1. 初始状态：所有对象标记为白色
2. 根搜索：所有根对象标记为灰色
3. 遍历标记：取灰色对象 → 将其引用的对象置灰 → 自身置黑
4. 重复步骤 3，直到灰色队列为空
5. 清扫：回收所有白色对象

**根对象包括：** 全局变量、执行栈上的对象和指针、寄存器中的变量。

## 3. 漏标问题与写屏障

### 3.1 漏标条件

以下两个条件同时满足才会漏标：

1. **插入**：黑色对象新增了对白色对象的引用（黑 → 白）
2. **删除**：灰色对象删除了对白色对象的引用（灰 ✂ 白）

黑色对象不会再被扫描，白色对象失去被标记的机会 → 被错误回收。

### 3.2 插入写屏障（强三色不变式）

```
规则：黑 → 白 插入时，将白色强制变灰
```

禁止存在黑色对象到白色对象的直接引用。

1.5-1.7 版本在堆上启用插入写屏障，但**栈上没有屏障**——因为栈写入频率高，在当时硬件条件下开销不可接受。所以标记结束时需要 STW 重新扫描所有栈。

### 3.3 删除写屏障（弱三色不变式）

```
规则：灰 → 白 引用被删除时，将白色对象置灰
```

不禁止黑 → 白，但保证始终存在灰 → 白的路径。

### 3.4 混合写屏障（1.8+）

结合两种屏障，消除栈重扫描：

| 机制 | 来源 |
|------|------|
| 栈上对象全部置黑 | 消除栈扫描需求 |
| GC 期间栈上新对象也置黑 | 防止新对象漏标 |
| 堆上插入屏障（新引用 → 对象置灰） | 插入屏障 |
| 堆上删除屏障（被删除引用 → 对象置灰） | 删除屏障 |

## 4. 为什么不采用分代法和标记-整理法

| 方案 | 不采用原因 |
|------|-----------|
| 分代法 | 编译器静态逃逸分析将短生命周期对象分配在栈上，堆上新生代对象不多，分代收益小；且需要额外写屏障维护跨代引用 |
| 标记-整理/复制法 | 运行时内存分配基于 TCMalloc，碎片化程度低；Thread Cache 规避了锁竞争 |

Go 的 GC 设计哲学：**用编译期分析（逃逸 + 栈分配）减少 GC 压力，用并发标记减少停顿，用写屏障保证正确性。**

## 5. 总结

1. Go GC 从全 STW 演进到微秒级并发的关键是三色标记 + 混合写屏障；
2. 插入屏障保证强三色（无黑→白），删除屏障保证弱三色（有灰→白路径）；
3. 混合写屏障让栈无需单独扫描，彻底消除第二次 STW；
4. 逃逸分析 + TCMalloc 是 GC 设计取舍的基础——不需要分代法、不需要标记-整理。
