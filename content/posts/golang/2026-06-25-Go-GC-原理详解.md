# 重要

Go 1.8+ GC 使用并发三色标记 + 混合写屏障，STW 降至微秒级。核心设计取舍：编译器逃逸分析将短生命周期对象留在栈上使分代回收收益小；TCMalloc 内存分配减少了标记-整理的碎片化需求。

## 1. GC 算法演进

| 版本 | 算法 | STW 时长 |
|------|------|----------|
| Go 1.4 及以前 | 标记-清除（全程 STW） | 100ms+ |
| Go 1.5 ~ 1.7 | 三色并发标记 + 插入写屏障 + 栈重扫描 | 1-3ms（两次 STW） |
| Go 1.8+ | 三色并发标记 + 混合写屏障 | <100μs（一次 STW） |

1.5-1.7 为什么有两次 STW：

```text
┌─────┬─────────────┬─────────────┬─────────────┐
│ STW │   并发标记   │     STW     │  并发清扫     │
│ 开始 │ (应用+GC)   │     终止     │  (仅应用)    │
└─────┴─────────────┴─────────────┴─────────────┘
  ↑                 ↑               ↑
启用屏障           重新扫描栈       禁用屏障
扫描初始根                        完成标记
```

- 第一次 STW（准备阶段）：确保根对象在一致状态下被扫描，100-500μs
- 第二次 STW（终止阶段）：栈上没有写屏障，必须重新扫描所有栈来捕获变化，1-3ms

1.8+ 在栈上引入**混合写屏障**，消除了第二次 STW。

## 2. 三色标记法

三色标记将对象分为三类：

| 颜色 | 含义 |
|------|------|
| {{< gc-white >}}白色{{< /gc-white >}} | 待标记对象，潜在的垃圾对象 |
| {{< gc-gray >}}灰色{{< /gc-gray >}} | 正在处理的根节点，待解析其引用 |
| {{< gc-black >}}黑色{{< /gc-black >}} | 已标记，确认存活的对象 |

**标记过程：**

1. {{< gc-white >}}初始状态{{< /gc-white >}}：**所有对象** 标记为 {{< gc-white >}}白色{{< /gc-white >}}
2. {{< gc-gray >}}根搜索{{< /gc-gray >}}：所有 **根对象** 标记为 {{< gc-gray >}}灰色{{< /gc-gray >}}
<details><summary>根对象说明</summary>

{{< gc-gray >}}根对象 = 初始节点{{< /gc-gray >}}，包括：

1. **全局变量**：程序在编译期就能确定的那些存在于程序整个生命周期的变量
2. **执行栈上的对象或指针**：每个 goroutine 都包含自己的执行栈，这些栈上的对象包含栈上的变量及指向分配的堆内存区块的指针
3. **寄存器中的变量**：寄存器的值可能表示一个指针，参与计算的这些指针可能指向某些赋值器分配的堆内存区块

</details>
3. 遍历标记：取 {{< gc-gray >}}灰色{{< /gc-gray >}} 对象 → 将其 **引用的对象** 置 {{< gc-gray >}}灰{{< /gc-gray >}} → 再将 **自身** 置 {{< gc-black >}}黑{{< /gc-gray >}} （自身没有应用的对象，就只将自身置黑）
4. 重复步骤 3，直到 {{< gc-gray >}}灰色队列{{< /gc-gray >}} 为空
5. {{< gc-white >}}清扫{{< /gc-white >}}：回收所有 {{< gc-white >}}白色{{< /gc-white >}} 对象

<details><summary>标记完成的标志</summary>

第3步，不论是否有引用，都会将{{< gc-gray >}}自身(灰){{< /gc-gray >}} 置 {{< gc-black >}}黑{{< /gc-gray >}}。因此，{{< gc-gray >}}灰色队列{{< /gc-gray >}}最终会变空，这也是标记完成的标志。

</details>

### 2.1 三色不变性

GC 出现错误回收必须同时满足两个条件：

1. 存在 {{< gc-black >}}黑色对象{{< /gc-black >}} 对 {{< gc-white >}}白色对象{{< /gc-white >}} 的引用（**插入**：{{< gc-white >}}白色对象{{< /gc-white >}}被挂在{{< gc-black >}}黑色对象{{< /gc-black >}}下）
2. 不能从任何 {{< gc-gray >}}灰色对象{{< /gc-gray >}} 追踪到该 {{< gc-white >}}白色对象{{< /gc-white >}}（**删除**：{{< gc-gray >}}灰色对象{{< /gc-gray >}} 对 {{< gc-white >}}白色对象{{< /gc-white >}} 的引用遭到破坏）

{{< keypoint >}}
{{< gc-black >}}黑色{{< /gc-black >}}对象不会再被扫描，{{< gc-white >}}白色{{< /gc-white >}}对象失去了被标记的机会 → 被错误回收。
{{< /keypoint >}}

两种屏障分别破坏其中一个条件：

| 屏障类型 | 破坏条件 | 策略 |
|----------|----------|------|
| **强三色不变式**（插入写屏障） | 条件一 | 不允许存在 {{< gc-black >}}黑色对象{{< /gc-black >}} 对 {{< gc-white >}}白色对象{{< /gc-white >}} 的引用 |
| **弱三色不变式**（删除写屏障） | 条件二 | 保证存在 {{< gc-gray >}}灰色对象{{< /gc-gray >}} 对 {{< gc-white >}}白色对象{{< /gc-white >}} 的引用 |

## 3. 漏标问题与写屏障

### 3.1 插入写屏障（强三色不变式）

```
规则：{{< gc-black >}}黑{{< /gc-black >}} → {{< gc-white >}}白{{< /gc-white >}} 插入时，将{{< gc-white >}}白色{{< /gc-white >}}强制变{{< gc-gray >}}灰{{< /gc-gray >}}
```

破坏条件一，不允许存在{{< gc-black >}}黑色对象{{< /gc-black >}}对{{< gc-white >}}白色对象{{< /gc-white >}}的直接引用。

1.5-1.7 版本在堆上启用插入写屏障，但**栈上没有屏障**——栈写入频率高，开销不可接受。所以标记结束时需要 STW 重新扫描所有栈。

### 3.2 删除写屏障（弱三色不变式）

```
规则：{{< gc-gray >}}灰{{< /gc-gray >}} → {{< gc-white >}}白{{< /gc-white >}} 引用被删除时，将{{< gc-white >}}白色{{< /gc-white >}}对象置{{< gc-gray >}}灰{{< /gc-gray >}}
```

破坏条件二，保证始终存在{{< gc-gray >}}灰色对象{{< /gc-gray >}}对{{< gc-white >}}白色对象{{< /gc-white >}}的引用路径。

### 3.3 混合写屏障（1.8+）

结合两种屏障，消除栈重扫描：

| 机制 | 来源 |
|------|------|
| 栈上对象全部置 {{< gc-black >}}黑{{< /gc-black >}} | 消除栈扫描需求 |
| GC 期间栈上新对象也置 {{< gc-black >}}黑{{< /gc-black >}} | 防止新对象漏标 |
| 堆上插入屏障（新引用 → 对象置 {{< gc-gray >}}灰{{< /gc-gray >}}） | 插入屏障 |
| 堆上删除屏障（被删除引用 → 对象置 {{< gc-gray >}}灰{{< /gc-gray >}}） | 删除屏障 |

## 4. 为什么不采用分代法和标记-整理法

| 方案 | 不采用原因 |
|------|-----------|
| 分代法 | 编译器静态逃逸分析将短生命周期对象分配在栈上，堆上新生代对象不多，分代收益小；且需要额外写屏障维护跨代引用 |
| 标记-整理/复制法 | 运行时内存分配基于 TCMalloc，碎片化程度低；Thread Cache 规避了锁竞争 |

Go 的 GC 设计哲学：**用编译期分析（逃逸 + 栈分配）减少 GC 压力，用并发标记减少停顿，用写屏障保证正确性。**

## 5. 总结

1. Go GC 从全 STW 演进到微秒级并发的关键是三色标记 + 混合写屏障；
2. 插入屏障保证强三色（无{{< gc-black >}}黑{{< /gc-black >}}→{{< gc-white >}}白{{< /gc-white >}}），删除屏障保证弱三色（有{{< gc-gray >}}灰{{< /gc-white >}}→{{< gc-white >}}白{{< /gc-white >}}路径）；
3. 混合写屏障让栈无需单独扫描，彻底消除第二次 STW；
4. 逃逸分析 + TCMalloc 是 GC 设计取舍的基础——不需要分代法、不需要标记-整理。
