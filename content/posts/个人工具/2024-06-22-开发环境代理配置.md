# 重要

内网开发环境需要代理访问 GitHub、gcr.io 等外网资源，同时内网仓库（Git、Registry）必须直连。本文覆盖浏览器 → Git → Docker → Minikube 全链路代理配置。

## 1. Git 代理：外网走代理，内网直连

需求：GitHub 仓库走代理，公司内网 Git 仓库直连。

### 环境变量方式（推荐）

```bash
export https_proxy=http://127.0.0.1:10800/
export http_proxy=http://127.0.0.1:10800/
export all_proxy=socks5://127.0.0.1:1088/

# 内网域名不走代理，空格分隔
export no_proxy=".service.rd .icos.city 127.0.0.1 localhost"
```

### git config 方式

针对特定仓库禁用代理（不依赖环境变量）：

```bash
# 仓库级别：为该仓库设置空代理
git config --local --add http.proxy ""

# remote 级别：仅为某个远端设置
git config --local --add remote.origin.proxy ""
```

### Github 域名方式（仅 github 走代理）

```bash
git config --global http.https://github.com.proxy http://127.0.0.1:10808
```

这样只有 GitHub 走代理，其他域名直连，无需 no_proxy 配置。

## 2. Docker 代理：拉取 gcr.io 等外网镜像

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d/
sudo vim /etc/systemd/system/docker.service.d/http-proxy.conf
```

```conf
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:10800"
Environment="HTTPS_PROXY=http://127.0.0.1:10800"
Environment="ALL_PROXY=socks5://127.0.0.1:1088"
Environment="NO_PROXY=localhost,127.0.0.1,reg.chebai.org"
```

重启生效：

```bash
systemctl daemon-reload
systemctl restart docker
```

验证：

```bash
systemctl show --property=Environment docker
```

## 3. Minikube：国内镜像替代

无需代理，直接用国内 registry mirror：

```bash
minikube start --registry-mirror=https://registry.docker-cn.com
```

或指定阿里云镜像仓库：

```bash
minikube start --vm-driver=none \
  --registry-mirror=https://registry.docker-cn.com \
  --image-repository=registry.cn-hangzhou.aliyuncs.com/google_containers
```

## 4. 验证

```bash
# Git
git clone https://github.com/hex-go/hex-go.github.io.git

# Docker
```
