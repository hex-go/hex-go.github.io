## 2. 两条脉络的衔接逻辑

系列按两条线索展开，在「跨主机 Pod 为什么不通」处汇合：

### 脉络 A（自底向上）：网络怎么工作 → Docker 怎么接入 → K8S 为什么需要 CNI

```
主机怎么转发包（网卡/路由/网关/ARP/直连路由）
  ↓
Docker 怎么把容器接入主机网络（namespace/veth/bridge/SNAT）
  ↓
K8S 为什么需要跨主机 Pod 互通
```

### 脉络 B（自顶向下）：K8S 要什么 → IPAM + 路由转发 → Overlay/路由方案分类树

```
K8S 网络假设（4 条）
  ↓
要跨节点，必须解决两个问题
  ↓
① 给 Pod 分 IP（IPAM）
② 让包送达目的 Pod（路由转发）
  ↓
路由转发的两条路：Overlay 封装 vs 路由不封装
```

### 衔接点：跨主机 Pod 为什么不通

- 脉络 A 走到这里：Docker bridge 只能解决单机，跨节点二层不通
- 脉络 B 从这里接上：要跨节点，必须解决 IPAM + 路由转发

## 3. CNI 解决的两件事（分类树根节点）

CNI 标准本质上解决两件事：

1. **IPAM（IP 地址管理）**——给 Pod 分什么 IP、怎么避免冲突
2. **连通性（路由转发）**——包怎么从源 Pod 送到目的 Pod

所有 CNI 插件的能力都可以归到这两个维度。分类树沿第二条展开：

```
CNI 解决的两件事
├── IPAM：给 Pod 分 IP
│   ├── host-local（静态子网分配）
│   ├── calico-ipam（动态分配）
│   └── dhcp
│
└── 连通性：怎么送达
    ├── Overlay — 封装隧道
    │   ├── UDP（应用层封装，用户态，性能差，仅演示）
    │   ├── VXLAN（内核态 L2-in-UDP，生产通用）
    │   └── IPIP（内核态 IP-in-IP，纯三层封装）
    └── 路由 — 不封装
        ├── HostGW（静态路由，要求二层互通）
        └── BGP（动态路由，三层互通）
```

## 4. 非重复原则

每篇文章的职责边界：

| 篇 | 职责 | 从分类树取什么 |
|---|---|---|
| ① 概念入门 | 讲全貌和分类逻辑——为什么分 Overlay/路由，每类的核心思想 | 整棵树的骨架 |
| ② Flannel | 讲具体怎么做——包怎么封装、路由表长什么样、抓包验证 | 取树中 3 个叶子：UDP/VXLAN/HostGW |
| ③ Calico | 讲具体怎么做——BGP 怎么传播路由、IPIP 封装、NetworkPolicy | 取树中 3 个叶子：BGP/IPIP/VXLAN |
| ④ 选型对比 | 讲怎么选——横向对比 + 决策树 + Canal 合并 | 对整棵树做横向比较 |
| ⑤ CNI 开发指南 | 讲怎么基于 CNI 规范自己开发——分层架构、开发步骤、注意事项 | 不碰分类树，独立维度 |
| ⑥ 流量路径 | 讲 Pod/Service/Ingress/Egress——CNI 只解决 Pod 间，Service 以上由 kube-proxy + CNI 共同完成 | 不碰分类树，独立维度 |
| ⑦ 排障实战 | 讲出问题怎么查 | 工具链，独立维度 |

一句话：**①篇种树，②③篇深入枝叶，④篇比较果实，⑤篇自己动手，⑥⑦篇换视角看流量和排障。**
